## Context

`POST /chat` уже возвращает `sources` с `title` и `chunk_text`, а гостевой
`conversation_id` хранится в `sessionStorage`. До этого изменения UI показывал
только disabled-кнопку во время запроса, скрывал цитату и не давал очистить
гостевой контекст. Next.js dev-сервер также отклонял клиентские чанки при
открытии контейнерного стенда через `127.0.0.1`, оставляя страницу без
гидрации.

## Goals / Non-Goals

**Goals:**

- Дать понятную обратную связь во время генерации и Vision-анализа.
- Сделать источники проверяемыми через раскрываемую цитату.
- Дать гостю безопасный reset только локального контекста.
- Сделать интерфейс визуально последовательным при загрузке экранов.
- Поддержать локальный Docker dev-стенд на loopback-адресе.

**Non-Goals:**

- Менять `POST /chat`, persist диалогов или backend API.
- Добавлять SSE/streaming, отмену backend-запроса или новый серверный endpoint.
- Сбрасывать данные уже созданного диалога в базе.

## Decisions

### 1. Индикатор связан с существующей мутацией

Использовать `sendMutation.isPending`, а не дополнительное состояние. При
наличии `pendingImage` показывать текст Vision-анализа, в остальных случаях —
формирование ответа. Так UI не может остаться в ожидании после завершения или
ошибки мутации.

### 2. Цитаты раскрываются внутри сообщения

Источник — кнопка в bubble сообщения, которая переключает локальный блок с
`chunk_text`. Это использует уже переданные API-данные и не требует modal,
tooltip или нового запроса за документом.

### 3. Reset изолирован version-маркером

Reset удаляет `guest_conversation_id`, очищает draft, вложение и локальные
сообщения. Счётчик версии отделяет новый UI-сеанс от незавершённого запроса:
поздний ответ прежнего диалога игнорируется и не возвращает старый ID или
историю.

### 4. Motion живёт в базовых UI-поверхностях

Общие CSS-классы добавляются в `Card`, таблицы, dialog, шапки и sidebar, чтобы
новые и существующие страницы получали единый эффект без библиотек анимации.
`prefers-reduced-motion` отключает все созданные анимации. Альтернатива —
анимировать каждую страницу вручную; она приводит к пропускам и дублированию.

### 5. Loopback origin разрешён только для разработки

`next.config.ts` разрешает `127.0.0.1` через `allowedDevOrigins`. Это
устраняет блокировку dev-ресурсов Next.js при Docker-запуске и не добавляет
внешних origin.

## Risks / Trade-offs

- [Поздний ответ backend после reset] → version-маркер не даёт ему изменить
  новый локальный сеанс.
- [Избыточная анимация] → короткие анимации только поверхностей и отключение
  через системную настройку reduced motion.
- [Клиентские ресурсы dev-сервера недоступны] → явный allowlist единственного
  loopback-host, подтверждённый ручной проверкой Docker-стенда.

## Migration Plan

1. Развернуть frontend вместе с обновлённой конфигурацией Next.js.
2. При откате удалить UI-классы и `allowedDevOrigins`; хранимые разговоры и
   backend-контракт не требуют миграции.
