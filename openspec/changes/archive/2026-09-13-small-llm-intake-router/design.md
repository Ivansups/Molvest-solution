## Context

Motivation — см. `proposal.md — Why`. Сейчас `handoff_detect` (OpenRouter
YES/NO, фолбэк GigaChat Lite) стоит после `classify` и до кэша/RAG, но
отвечает только за хэндофф: приветствия, «ты тут?» и оффтоп доезжают до
`retrieve` + `generate` GigaChat. Код уже переписан: нода `router` возвращает
маршрут из кодов (`SUPPORT`/`HANDOFF`/`GREETING`/`AWAY_CHECK`/`OFFTOPIC`) +
короткий ответ, граф заканчивается на коротких маршрутах без GigaChat.
Требования зафиксированы в дельте `openspec/specs/agent-dialog-graph`.

## Goals / Non-Goals

**Goals:**
- Отсечь нерелевантный трафик до RAG одной дешёвой LLM-проверкой вместо
  полного цикла GigaChat.
- Сохранить деградацию без OpenRouter: правила → GigaChat Lite → эскалация.
- Не путать маршрутизацию дампом Vision и не читать «позвать оператора?» как
  SUPPORT/не резать странные 1С-вопросы как OFFTopic.

**Non-Goals:**
- Генерация ответов по 1С на малой модели, эмбеддинги, перенос логики в банки
  промптов, изменение каналов и фронтенда, CSAT.

## Decisions

**1. Нода `router` вместо `handoff_detect`, интерфейс `route()` вместо
`is_handoff_request()`.** One call отвечает на целый набор вопросов:
хэндофф/приветствие/away/оффтоп/support. Альтернатива (последовательные
Вызовы»: «сначала хэндофф, потом оффтоп») — больше запросов к платной LLM и
сложнее фолбэки. Принят единый строгий формат «код на первой строке, ответ
ниже».

**2. Жёсткий парсинг с fail-closed.** `parse_router_decision` принимает
только код из известного словаря; неоднозначный/пустой ответ —
`OpenRouterError`, дальше фолбэк. Никогда «мусор» не трактуется как SUPPORT:
в противном случае спам доезжал бы до RAG и путал бы оператора.

**3. Фолбэк: правила → GigaChat Lite.** Без ключа/при сбое OpenRouter —
regex для коротких «чистых» реплик (`_HANDOFF_RULES`, `_GREETING_ONLY`,
`_AWAY_CHECK`, терпимы к хвостовой пунктуации). Не решили правила — тот же
YES/NO хэндофф-промпт через GigaChat-2 (Lite). Оба упали — эскалация с
`DETECTOR_FAILURE_REASON`. Альтернатива (GigaChat Lite для всех маршрутов)
дорога и не умеет оффтоп/приветствие; правила сохраняют бесплатный дефолт.

**4. Роутер читает `text` гостя, не `query`.** `query` после `vision` — дамп
скриншота; маршрутизация по нему путала бы приветствие с описанием. Зафиксировано
тестом `test_route_intent_uses_guest_text_not_vision_dump`.

**5. `force_handoff` срезает классификатор до его вызова.** Флаг —
гражданский хэндофф (кнопка виджета); не должен зависеть от LLM. Ветка — в
самом начале `route_intent`.

**6. Greeting/away/offtopic не пишутся в кэш ответа.** В `_generate_and_cache`
попадаем только по пути SUPPORT; короткий ответ роутера возвращается состоянием
без записи кэша. Инвариант «кэш — только уверенные ответы по базе знаний»
сохранён (`spec. agent-dialog-graph — Answer cache is checked before retrieve`).

**7. `build_graph` сохраняет публичный параметр `handoff_classifier`.**
Тесты и каналы передают классификатор значением; переименование в
`intake_classifier` — косметика, вне scope этого change.

## Risks / Trade-offs

- **Ложно-позитивное отсечение оффтопа** (вопрос по 1С странной формулировкой)
  → промпт жёстко требует «при сомнении — SUPPORT», регулярки ловят только
  короткие чистые реплики; вопрос с приветствием в начале не режется
  (`^...$`, только один шаблон).
- **Зависимость от доступности OpenRouter | Платный трафик** → отсутствие
  ключа и сбои деградируют на правила + GigaChat без потери хэндоффа; `max_tokens=256`,
  `temperature=0`; генерирует только короткие шаблоны, не ответы по 1С.
- **Дрейф кодов в промпт модели** (вернёт `SOMETHING` вместо `SUPPORT`) →
  fail-closed парсинг + фолбэк, ошибка логируется, маршрут решается правилами.
- **«спасибо» получает шаблон приветствия, а не развёрнутый диалог** → осознанно:
  короткая реплика не несёт задачи БЗ; вернуться к полному ответу можно
  сужением `_GREETING_ONLY`.

## Migration Plan

- Конфиг: в `.env.example` добавлены `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`,
  `OPENROUTER_BASE_URL`, `OPENROUTER_TIMEOUT`. Без ключа система работает как
  раньше (правила + GigaChat Lite), поэтому rolling-деплой без флагов.
- Миграций БД нет; Alembic не затрагивается.

## Open Questions

- Профит-метрика отсечения (доля GREETING/AWAY/OFFTOPIC на реальном трафике)
  и конечный провайдер малой модели — решаются после пилота, не меняя спеки и
  задачи.
