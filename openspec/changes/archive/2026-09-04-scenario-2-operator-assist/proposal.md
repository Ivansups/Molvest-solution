## Why

Сценарий 2 ТЗ («автоматическое подключение к чату») не реализован: после эскалации агент замолкает, оператор не может запросить черновик, ответить в том же диалоге и закрыть тикет. Без этого контура нельзя показать, что агент работает за спиной оператора.

Generate на каждое сообщение гостя не делаем: это дорогой вызов GigaChat. Черновик считается только когда оператор нажал «Сгенерировать ответ».

## What Changes

- Слабый поиск по-прежнему эскалирует **без** generate. Гостю фраза про оператора, черновик пустой.
- Пока диалог `escalated` и режим `draft`, новые сообщения гостя только пишутся в ленту: без retrieve, без generate, без кэша ответа.
- Черновик появляется только по кнопке оператора (`POST …/suggest`). Повтор кнопки пересобирает черновик.
- Режим `auto` — отдельный путь, где агент может ответить гостю сам. По умолчанию `draft`.
- Ответ оператора и `escalated → resolved` через сервис статусов.
- Консоль показывает живые эскалации; гость видит ответы оператора без перезагрузки.
- Контракт `POST /chat` для гостя не ломаем; черновик в нём не отдаём.

## Capabilities

### New Capabilities

- `operator-assist`: режим draft/auto, кнопка «Сгенерировать ответ» как единственный generate для черновика, ответ оператора, закрытие тикета, UI операторской.

### Modified Capabilities

- `agent-dialog-graph`: в `draft` на `escalated` гостевой ход не ходит в GigaChat; слабый скор на `open` по-прежнему без generate.
- `conversation-records`: роль `operator`, поле черновика (заполняется только suggest), запись ответа оператора и resolve.
- `support-console-ui`: `/operator` и support-чат на живых эскалациях, кнопка генерации, отправка и resolve.
- `guest-chat-ui`: после эскалации гость видит ответы оператора; черновик ему не показывается.

## Impact

- Backend: граф (пропуск LLM на `escalated`+`draft`), persist, модели, Alembic, API messages/resolve/suggest, `OPERATOR_ASSIST_MODE`.
- Frontend: панель оператора с кнопкой генерации, support/guest chat.
- Тесты: эскалация без generate; follow-up без LLM; suggest пишет только черновик; ответ и resolve.
- Вне scope: Bitrix/Redmine, SSE, API настроек, `/api/operator/tickets`, обучение на кейсах.
