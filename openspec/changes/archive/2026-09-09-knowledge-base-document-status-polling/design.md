## Context

Админская база знаний получает список через `documentService.listDocuments()` и
карточку через `documentService.getDocument()`. Backend возвращает документ со
статусом `PENDING`, пока фоновая индексация не завершена, после чего статус
становится `INDEXED` или `FAILED`. React Query уже используется на обеих
страницах, а глобальные настройки отключают polling по умолчанию.

## Goals / Non-Goals

**Goals:**

- Обновлять список без ручного F5, если хотя бы один документ текущей страницы
  ещё индексируется.
- Обновлять открытую карточку до финального статуса.
- Прекращать сетевые запросы после `INDEXED` или `FAILED`.
- Сохранить текущую пагинацию, фильтры, cache keys и сервисный слой.

**Non-Goals:**

- Изменения FastAPI, фоновой индексации или схемы API.
- WebSocket/SSE и глобальный мониторинг документов вне текущей выдачи.
- Polling завершённых документов.
- Изменение поведения мутаций загрузки, удаления и reindex.

## Decisions

### 1. Динамический `refetchInterval` в существующих `useQuery`

В запросе списка callback проверяет `query.state.data?.items` и возвращает
`4000` мс, если есть `PENDING`, иначе `false`. В запросе карточки callback
проверяет `query.state.data?.status` и использует ту же логику. В React Query 5
callback получает актуальный объект query, поэтому после ответа с финальным
статусом следующий интервал не планируется.

Альтернатива — постоянный интервал и ручная остановка через эффект. Она создаёт
лишние запросы и усложняет синхронизацию с cache, поэтому не используется.

### 2. Polling только активного запроса

Карточка сохраняет `enabled: Boolean(docId)`, а список продолжает использовать
свои существующие query key с учётом страницы и фильтров. Поэтому polling не
запускается до появления идентификатора и не смешивает результаты разных
выдач.

### 3. Общий интервал без новой конфигурации

Интервал фиксирован константой `DOCUMENT_POLL_INTERVAL_MS = 4000` в каждом
компоненте. Это соответствует требованию разумного таймаута и не добавляет
неиспользуемую настройку в конфиг.

## Risks / Trade-offs

- [Текущая страница не содержит PENDING-документ] → polling не запускается;
  документ на другой странице начнёт обновляться при открытии этой страницы.
- [Окно браузера неактивно] → браузер может ограничить таймеры; при возврате
  React Query выполнит обычный refetch по существующей политике приложения.
- [Backend не меняет статус] → запросы продолжатся до закрытия/ухода со страницы,
  что является ожидаемым поведением для незавершённой индексации.

## Migration Plan

1. Развернуть только изменения frontend-компонентов.
2. Проверить `lint` и `typecheck`, затем выполнить тесты frontend.
3. Откатить можно удалением двух опций `refetchInterval` и бейджа статуса;
   миграции данных и backend rollout не нужны.

## Open Questions

Нет. Поле `status` и значения `PENDING`, `INDEXED`, `FAILED` подтверждены
OpenSpec-контрактом документов.
