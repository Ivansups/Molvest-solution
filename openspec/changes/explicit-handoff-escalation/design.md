## Context

Эскалация в графе сейчас решает `retrieve`: `escalated = confidence < threshold`
(см. `specs/agent-dialog-graph`). Классификация (`classify`) работает без LLM —
только `empty`/`support`. Детект хэндоффа (просьбы передать диалог человеку)
вынесена в отдельную ноду `handoff_detect`, вызывающую лёгкую LLM через OpenRouter:
правила-регэкспы хрупки (неполный словарь формулировок, ложные срабатывания на
вопросах-фактах «как позвать оператора»). Персист эскалации уже сквозной:
`persist_turn` создаёт `Escalation` с причиной; статус меняется только через
`conversation_status.transition_status`.

## Goals / Non-Goals

**Goals:**
- Детект явной просьбы о хэндоффе через лёгкую LLM (OpenRouter), не правила.
- Фолбэк в `support` при сбое классификатора — чат не роняется.
- Эскалация через существующий центральный сервис статуса, штатная фраза гостя
  и тикет в консоли — без изменения контракта `POST /chat`.
- Отключение детекта при пустом ключе OpenRouter — обратная совместимость.

**Non-Goals:**
- Классификация хэндоффа по истории диалога (контекст нескольких реплик) —
  текущий подход классифицирует каждое сообщение отдельно.
- Раздельный `reason`/runbook для оператора (подробности запроса) — причина будет
  единой строкой, как и сейчас.
- Замена GigaChat для ответов/эмбеддингов — OpenRouter используется только для
  детекта хэндоффа.

## Decisions

### D1: Отдельная нода `handoff_detect` с LLM-классификатором, не правила в `classify`

Детект хэндоффа вынесен в отдельную ноду графа `handoff_detect`, вызывающую
лёгкую LLM через `OpenRouterClassifier`. Причины:
- LLM точнее покрывает варианты формулировок, чем регэкспы; «нужен человек»,
  «хочу поговорить с человеком», «позовите специалиста» — разные конструкции.
- `classify` остаётся без LLM (инвариант «без модели» в этой ноде сохраняется;
  LLM вызывается в соседней ноде).
- Порог точности выше, чем у правил: вопрос «как позвать оператора в 1С» — это
  «как сделать X в 1С», не просьба о передаче, и LLM это понимает.
- Нет новых зависимостей: OpenRouter API совместим с OpenAI-форматом.

**Альтернатива:** правила-регэкспы в `classify`. Отвергнуто: неполный словарь
формулировок, ложные срабатывания («передайте документы оператору» → хэндофф
вместо support), необходимость поддерживать список исключений.

### D2: Новый intent `handoff` с эскалацией от `handoff_detect`, ранний выход из графа

Маршрут: `classify` → `handoff_detect` → `END` (при handoff) или
`lookup_cache` (при support). Если `handoff_detect` определяет хэндофф,
intent ставится `handoff`, `escalated=true` и `escalation_reason` — сразу в END,
минуя кэш, retrieve и generate.

**Альтернатива:** роутинг `handoff` через retrieve и полагание на низкий скор.
Неверно: запрос «позовите оператора» может найти релевантный чанк БЗ и ответить
вместо эскалации.

### D3: Фолбэк при сбое классификатора — `support`

При `OpenRouterError` (сеть, HTTP, неразборчивый ответ) нода `handoff_detect`
возвращает `{}`, intent остаётся `support` и граф продолжает обычный путь
(retrieve/generate). Чат не роняется: отсутствие хэндоффа лучше, чем недоступность.

Пустой `OPENROUTER_API_KEY` — `classifier.is_configured()` возвращает `False`,
нода пропускается без вызова LLM.

### D4: Строгий промпт-классификатор на лёгкой модели

Системный промпт: «Ты классификатор запросов техподдержки ПО 1С. Отвечай
строго ОДНИМ словом: YES если пользователь просит передать диалог живому
человеку … или NO во всех остальных случаях. Никакого текста кроме YES или NO.»
`max_tokens=5`, `temperature=0`, модель по умолчанию
`meta-llama/llama-3.1-8b-instruct`.

### D5: Причина эскалации прокидывается сквозь состояние графа

Поле `escalation_reason` в `AgentState` → `persist_turn(escalation_reason=...)`.
`conversations.py` по-прежнему создаёт `Escalation` идемпотентно и меняет статус
только через `transition_status`; причина по умолчанию (низкий скор) остаётся.
Это не трогает схему БД и API — только значение поля `reason`.

**Альтернатива:** захардкодить причину в `persist_turn` по факту `escalated`.
Метод не знает источник эскалации (граф уже его знает), пришлось бы добавлять
флаг — грязнее, чем проброс строки.

## Risks / Trade-offs

[Ложные срабатывания LLM: «передайте документы оператору» может уйти оператору] →
Минимальный риск: просьба «передать/соединить» с адресатом-человеком почти всегда
означает хэндофф; при спорном случае эскалация безопаснее ответа мимо темы.
Лёгкая модель хорошо различает контекст.

[Ложные негативы: LLM решит, что «позовите оператора» — не просьба] →
Промпт явно описывает императивы и желания; модель достаточно сильна для
узкой задачи YES/NO.

[Латентность классификатора ~1–3 сек] → Модель лёгкая, timeout 10 сек;
avg латентность OpenRouter 8B ~1–2 сек; общая задержка ответа ~3–5 сек
( vision + classify + handoff + retrieve + generate ), что укладывается
в SLA.

[Стоимость вызова OpenRouter] → meta-llama/llama-3.1-8b-instruct бесплатен
или ~$0.0001/запрос; детект на каждом непустом ходе — ~50K запросов/мес
≈ $5.

## Migration Plan

- Чистый деплой: код обратно совместим, миграций БД нет, контракт API не
  меняется. При пустом `OPENROUTER_API_KEY` — поведение как раньше (без детекта).
- Откат: revert правок `handoff_detect`/`graph`/`openrouter_client` — прошлое
  поведение («только низкий скор») возвращается без миграций.
