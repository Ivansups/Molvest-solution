## Context

Эскалация в графе сейчас решает `retrieve`: `escalated = confidence < threshold`
(см. `specs/agent-dialog-graph`). Классификация (`classify`) работает без LLM —
только `empty`/`support`, переиспользовать её правила — самый дешёвый способ поймать
просьбу о хэндоффе, не добавляя вызовов модели. Персист эскалации уже сквозной:
`persist_turn` создаёт `Escalation` с захардкоженной причиной «Низкая уверенность
ретривала». Статус меняется только через `conversation_status.transition_status`.

## Goals / Non-Goals

**Goals:**
- Детект явной просьбы о хэндоффе без LLM и без новых внешних зависимостей.
- Эскалация через существующий центральный сервис статуса, штатная фраза гостя
  и тикет в консоли — без изменения контракта `POST /chat`.

**Non-Goals:**
- Классификация хэндоффа по истории диалога (контекст нескольких реплик) —
  в будущем можно усилить LLM-классификатором, спеки не меняя.
- Раздельный `reason`/runbook для оператора (подробности запроса) — причина будет
  единой строкой, как и сейчас.

## Decisions

### D1: Детект правилами в `classify`, не отдельный узел графа

Просьба о хэндоффе — это классификация интента, логичное место — существующий
узел `classify` (без LLM). Отдельный узел `handoff` плодил бы лишний шаг для
одного правила и усложнял граф.

**Альтернатива:** отдельный узел + `LLM`-классификатор. Отвергнуто: дороже по
латенси (лишний вызов GigaChat), а правила дают требуемую точность для узкого
набора фраз, и уже так работает весь `classify` (несёт инвариант «без модели»).

### D2: Новый intent `handoff` с эскалацией от `classify`, ранний выход из графа

`classify` возвращает `intent=handoff`, `escalated=true` и `escalation_reason`.
`_after_classify` маршрутизирует `handoff` сразу в `END`, минуя кэш, `retrieve`
и `generate`. Это сохраняет проверяемость: словарь результата графа говорит
`escalated`, как и в ветке низкого скора.

**Альтернатива:** пусть `handoff` идёт через `retrieve` и полагается на низкий скор.
Неверно: запрос «позовите оператора» может найти релевантный чанк БЗ и ответить,
а не эскалировать.

### D3: Правила-регэкспы с исключением вопросов-фактов

Два паттерна: (1) императив «позовите/вызовите/передайте/соедините/…» + адресат
(оператор/специалист/человек/менеджер/сотрудник); (2) желание «нужен человек»,
«хочу поговорить с человеком». Перед проверкой отсекаются запросы, начинающиеся
с «как…», «куда», «зачем», «можно ли», «подскажите как», «расскажите как» — это
вопросы к базе знаний про оператора, а не просьба о хэндоффе.

**Альтернатива:** список полных фраз-сниппетов. Менее гибко; регэкспы покрывают
варианты словоформ («оператору/оператором», «позовите/позови») без разрастания списка.

### D4: Причина эскалации прокидывается сквозь состояние графа

Поле `escalation_reason` в `AgentState` → `persist_turn(escalation_reason=...)`.
`conversations.py` по-прежнему создаёт `Escalation` идемпотентно и меняет статус
только через `transition_status`; причина по умолчанию (низкий скор) остаётся.
Это не трогает схему БД и API — только значение поля `reason`.

**Альтернатива:** захардкодить причину в `persist_turn` по факту `escalated`.
Метод не знает источник эскалации (граф уже его знает), пришлось бы добавлять
флаг — грязнее, чем проброс строки.

## Risks / Trade-offs

[Ложные срабатывания правил: «передайте документы оператору» может уйти оператору] → Минимальный риск: просьба «передать/соединить» с адресатом-человеком почти всегда означает хэндофф; при спорном случае эскалация безопаснее ответа мимо темы.

[Ложные негативы: редкие формулировки («соединиться со специалистом») не поймаются правилом] → Правила покрывают словарь просьб; LLM-классификатор — заявленный non-goal, расширение правил точечное.

[Отсечение «как …» может пропустить настоящую просьбу («как мне позвать оператора?»)] → Такая формулировка неоднозначна и исторически уходит в БЗ; оператор может эскалировать повторно.

## Migration Plan

- Чистый деплой: код обратно совместим, миграций БД нет, контракт API не меняется.
- Откат: revert правок `classify`/`graph`/`agent`/`conversations` — прошлое поведение
  («только низкий скор») возвращается без миграций.
