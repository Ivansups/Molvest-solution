## Why

Сценарий 2 ТЗ («автоматическое подключение к чату») сейчас замкнут на нашу консоль: draft/auto работает только в `/operator` и `/chat/support`, а агент не подписан на живой тред Bitrix «пользователь ↔ оператор». Оператор ведёт диалог в Bitrix, а подсказки агента к нему не доходят: черновик не готовится, в auto-режиме нет ответа в сам тред. Входящего адаптера Bitrix (маппинг id треда → `conversation_id`, №26) в коде нет, поэтому вместе с live-assist вводится минимальный импровизированный вебхук Bitrix.

## What Changes

- Новый `POST /webhook/bitrix`: входящее сообщение открытого треда (отправитель `user`/`operator`, текст, `thread_id`, `message_id` для идемпотентности, `workspace_id`).
- Таблица маппинга «id треда канала → `conversation_id`»: первое сообщение треда создаёт диалог, дальнейшие продолжают его.
- Идемпотентность: повтор события с тем же `message_id` не пишет дубли и не перегоняет граф (уникальный ключ `channel, message_id` + ранняя проверка).
- Живой тред использует тот же RAG/граф сценария 1; режим `draft`/`auto` берётся из runtime-настроек (`get_effective_operator_assist_mode`) на каждое событие — смена draft↔auto через `PUT /api/settings` без рестарта.
- **draft**: на сообщение пользователя готовится черновик (retrieve + generate) и пишется в `suggested_response` — оператор видит подсказку в треде и в консоли как зеркале. Ответ пользователю не уходит.
- **auto**: полный граф; высокий confidence → ответ пользователю в том же треде; низкий → эскалация (фраза гостю + строка `Escalation`).
- Сообщение от оператора не запускает граф — только пишется в ленту (пассивное слушание).
- `/operator` остаётся зеркалом операций, не заменой живого треда.

## Capabilities

### New Capabilities
- `bitrix-webhook`: Приём входящих сообщений живого треда Bitrix: webhook-контракт, классификация отправителя, маппинг id треда → `conversation_id`, идемпотентность повторов.
- `live-bitrix-thread-assist`: draft/auto в живом треде: черновик оператору, автоответ пользователю, эскалация по порогу, режим из runtime-настроек.

### Modified Capabilities
- `operator-assist`: `suggested_response` заполняется не только по кнопке «Сгенерировать» в консоли, но и автоматически в draft-режиме живого Bitrix-треда (требование «only path» сужается до консольного on-demand пути).

## Impact

- Backend: новые модели `ChannelThread`/`ChannelMessage` + Alembic `003_channel_threads`; пакет `channels/bitrix/` (webhook, схемы); сервис `services/live_thread.py`; регистрация роутера в `main.py`.
- Тесты: вебхук (user/operator/draft/auto/дубль/маппинг), смена режима через runtime-настройки, идемпотентность.
- Вне scope: реальный REST Bitrix (только импровизированный вебхук), Redmine, обучение на кейсах, фронтенд.
