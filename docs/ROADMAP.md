# Roadmap — Молвест AI-агент (7 дней)

Стек: **FastAPI + LangGraph + React + PostgreSQL + PGVector**
Дедлайн отборочного этапа: **11 сентября 2026**

Приоритет сценариев (по баллам/рискам):
1. Q&A чат-бот + RAG + эскалация — ядро оценки (GigaChat 20б + работоспособность 20б)
2. Управление базой знаний (админка) — легко показать, даёт баллы за код/UX
3. Анализ скриншотов 1С — сильно повышает "качество использования GigaChat"
4. Автоподключение к чату (Bitrix24/Redmine) — рискованный по интеграциям, делаем последним/упрощённо

---

## День 1 — Фундамент
- [ ] Инициализация репо: `apps/api` (FastAPI), `apps/web` (React), `infra` (docker-compose)
- [ ] PostgreSQL + PGVector контейнер, базовые модели (SQLAlchemy async): `documents`, `chunks`, `conversations`, `messages`, `escalations`
- [ ] Alembic миграции
- [ ] Получить токен GigaChat (SBER ID), проверить базовый вызов API из FastAPI
- [ ] .env / конфиг, секреты не в репо

## День 2 — RAG-ядро
- [ ] Пайплайн загрузки документов (Word/PDF/HTML/MD) → чанкинг → эмбеддинги → PGVector
- [ ] Сервис поиска по базе знаний (top-k retrieval + скор релевантности)
- [ ] LangGraph: граф "запрос → retrieval → генерация ответа GigaChat" (skeleton)
- [ ] Наполнить тестовую базу знаний реальными/примерными данными 1С

## День 3 — Сценарий 1: Q&A чат-бот
- [ ] Endpoint `/chat` — вопрос → RAG → ответ
- [ ] Порог уверенности (confidence threshold ~80%) → эскалация на оператора при низкой уверенности
- [ ] Логирование диалогов и эскалаций в БД
- [ ] E2E тест основного пользовательского сценария (это ключевой критерий на демо)

## День 4 — Сценарий 3: Анализ скриншотов
- [ ] Приём изображений (PNG/JPEG) в API
- [ ] OCR/vision (GigaChat vision или отдельный OCR + передача текста в GigaChat)
- [ ] Классификация проблемы (код ошибки, неверное поле, интерфейс) → рекомендации
- [ ] Интеграция в тот же диалоговый граф LangGraph (как ещё один узел/tool)

## День 5 — Сценарий 4: Админка базы знаний
- [ ] React: страница списка документов, загрузка/редактирование/удаление
- [ ] Переиндексация при изменении документа
- [ ] Дашборд метрик: % успешных ответов, среднее время ответа, число эскалаций
- [ ] Просмотр логов диалогов

## День 6 — Сценарий 2 (упрощённо) + интеграция + тестирование
- [ ] Мини-версия "автоподключения к чату": webhook/поллинг из Bitrix24 или Redmine (можно замокать, если нет доступа к реальным аккаунтам) → агент предлагает черновик ответа оператору
- [ ] Полный прогон всех 4 сценариев, фикс багов, стабильность
- [ ] Разворачиваем прототип на сервере/хостинге (нужен доступ 10 дней после соревнования)
- [ ] README с инструкцией запуска + архитектурная схема

## День 7 — Полировка и защита
- [ ] UX/UI шлифовка (чат-виджет, админка) — критерий 20 баллов
- [ ] Комментарии в коде на сложных участках, чистка репозитория
- [ ] Бонус "развитие решения": сформулировать 2–3 обоснованные идеи развития (новые каналы, доп. источники данных, масштабирование на другие отделы)
- [ ] Презентация по структуре: проблема → заказчик → диалог с заказчиком → концепция → как работает → демо → архитектура → эффект (с цифрами) → развитие → масштабирование
- [ ] Прогон демо-сценария по таймингу

---

## Риски / что держать в голове
- GigaChat должен быть **содержательным ядром**, не декорацией — явно показывать retrieval + генерацию + (по возможности) оркестрацию агента через него.
- Приоритет — рабочий прототип над красивой презентацией на этапе 1 (работоспособность = 20б, отдельно от UX).
- Bitrix24/Redmine интеграции — не блокировать ядро из-за отсутствия доступа, делать через мок/адаптер.
